# US-03 · Контролируемый таймаут AI-ревью

Статус: специфицировано до реализации; согласование двух агентных ролей.
Человеческая приёмка проводится при сдаче.

## Источник

В `../practice_01/product_management.md` нет пронумерованных US: есть три
сценария. Третий — «Таймаут LLM». В этой работе он обозначен US-03:
как разработчик/CI, я хочу получить понятную ошибку, если LLM отвечает
дольше 10 секунд, чтобы запрос не зависал и его можно было повторить.
US-01 — успешное ревью; US-02 — ограничение размера diff.

В `prenetation.pdf`, слайд 16, дополнительно требуются другой SDD-фреймворк,
две спецификации до/после, общий контракт, UI и логика, проверки и демо.
Выбран GitHub Spec Kit: constitution → specify → clarify → plan → tasks
→ implement → analyze. Команды агента выполняются как workflow;
`specify` CLI устанавливает инфраструктуру, но не генерирует реализацию.

## Приёмка

1. **AC-01, success/regression.** Given непустой diff ≤20000 Unicode
   code points, When POST /api/reviews, Then 200 с summary, risks (≤3), checks.
2. **AC-02, US-03.** Given cancellable LLM дольше 10 секунд, When ревью,
   Then 504 с error.code=llm_timeout; coroutine отменена; health отвечает
   во время ожидания; следующий normal запрос успешен.
3. **AC-03, UI.** Given timeout, When пользователь выбирает normal и
   нажимает «Повторить», Then diff сохранён и показан success. Во время
   loading повторная отправка заблокирована, старый результат скрыт.
4. **AC-04, boundary/error.** Given 20000/20001 Unicode code points,
   When POST, Then 200/413. Missing/null/non-string/blank/extra field и
   невалидный JSON → безопасный 422 до вызова провайдера.
5. **AC-05, rules.** Given распознаваемые секреты, сбой или сломанный
   JSON провайдера, When ревью, Then секреты замаскированы до generate;
   ошибки провайдера → 502 без внутренних данных; logs содержат только
   request_id, duration, status. UI отображает ответ как текст.

## Границы

Один локальный сервис, существующие маршруты POST /api/reviews и GET /health,
форма на GET /. Нет хранения diff, авторизации, очереди, автоматических
повторов, действий в GitHub или оценки качества реальной LLM. DemoProvider
детерминированный и прямо обозначен в UI. Реальный провайдер внедряется через
async Protocol; подключение коммерческого провайдера не входит в US-03.
