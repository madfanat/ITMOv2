# Сессия команды логики: спецификация до реализации

Дата: 2026-10-28. Исполнитель: независимый агент `logic_spec`.

## Полученное задание

Роль команды логики из слайда 16: без генерации кода подготовить отдельную
спецификацию третьей User Story, учесть P1-03, предложить API, отменяемый
10-секундный timeout, demo-провайдер и регрессионные проверки. Разрешены только
этот журнал и `specs/003-llm-timeout/drafts/logic.before.md`.

## Действия и наблюдения

Прочитаны исходные `context.md` и `product_management.md` практики 1.
В исходнике нет пронумерованного бэклога, но третий явно перечисленный сценарий —
таймаут LLM. Поэтому US-03 обозначает именно этот сценарий, а не выдуманную фичу.
Найдены обязательные ограничения: 20000 символов, секреты до провайдера,
10 секунд, структурированный ответ, ограничение рисков, отсутствие действий
GitHub и metadata-only logging.

## Предложенный результат

Создан независимый черновик `specs/003-llm-timeout/drafts/logic.before.md`.
Предложены 504 для таймаута, 502 для отказа/невалидного ответа, безопасная единая
оболочка ошибок, `X-Request-ID`, cooperative cancellation и demo-сценарии.
Девять критериев связывают требования с HTTP, unit и E2E проверками.

Для стыковки переданы вопросы о 504/502, request_id, управлении demo-режимом и
браузерном дедлайне. Результат не объявлен согласованным человеком. Код не менялся.

## Review финальных спецификаций до кода

Время проверки: 2026-10-28 13:52:46 UTC.
Прочитаны `logic.spec.md`, `contracts/api.md`, `ui.spec.md`,
`clarifications.md` и `plan.md` в `specs/003-llm-timeout/`.

Результат: финальная спецификация логики согласована с общим контрактом
по проверенным пунктам. Вопросы исходного черновика закрыты:

- Таймаут представлен 504/`llm_timeout` и состоянием UI `timeout`;
  provider/schema errors представлены 502 и состоянием `error`.
- `request_id` находится в `X-Request-ID` во всех ответах и дополнительно
  в общей оболочке ошибок; тело успеха сохраняет `summary/risks/checks`.
- Управление локальным DemoProvider выполняется `X-Demo-Scenario`
  per request. Контракт явно сообщает `demo: true` через `/api/config`;
  настоящий провайдер не подразумевается.
- Серверный дедлайн 10.0 секунд отделён от браузерных 15 секунд.
  Сетевой отказ не выдаётся за подтверждённый сервером timeout.
- Повтор ручной, исходный diff сохраняется, старый результат очищается;
  общий изменяемый сценарий провайдера запрещён.
- Unicode code points, безопасные 422/502 и metadata-only logs
  определены одинаково. Ограничения regex-маскировки и cooperative
  cancellation явно отражены в плане.

Существенных противоречий между UI, логикой и контрактом на этапе
спецификаций не найдено. Можно переходить к тестам и реализации;
доказательства фактической отмены, границ и поведения UI появятся после
выполнения проверок. Это review отдельного агента, не человеческая
приёмка и не подтверждение ещё не существующего кода.
