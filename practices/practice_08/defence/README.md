## Сценарий на 7–8 минут

1. Откройте `prototype.html` локально и переключите исходный экран, ввод, загрузку, результат, ручной разбор и ошибку. Сравните с приложением. На обоих экранах действие начинается в карточке «Обращение», ответ появляется в карточке «Результат». Покажите импорты Mantine в [App.tsx](../src/App.tsx), общую [тему](../src/theme.ts) и [стили](../src/styles.css).
2. Из корня репозитория запустите `make -C practices/practice_08/defence start`. Откройте `http://127.0.0.1:4173`. Нажмите **Классифицировать** с пустым заголовком, затем с `abc`. Форма выделяет поле и возвращает в него фокус. Затем нажмите **Заполнить пример**, откройте в DevTools вкладку **Network** и дважды нажмите **Классифицировать**. Пока кнопка заблокирована, нажмите Enter в заголовке. В Network должен остаться один POST. В правой панели появится `bug` и оценка уверенности модели.
3. Введите заголовок `Иногда всё странно` и описание `Не знаю, что именно происходит.`. В панели появится «Нужен ручной разбор». В n8n откройте `Execute classifier` и выход `Apply triage threshold`, чтобы показать переход от `{type: unknown, confidence: 0.7}` к `{classification: null}` на записанном прогоне. При новом вызове оценка модели может отличаться.
4. Во втором терминале выполните `make -C practices/practice_08/defence fault`, сохранив первый процесс. На `http://127.0.0.1:4174` отправьте пример. Подставленный для второго процесса неверный заголовок вызывает реальный отказ n8n. Из-за него приложение покажет ошибку и кнопку **Повторить**, а текст останется в полях. После восстановления настроек повтор отправил сохранённый пример и получил `bug` с уверенностью 95%. [Исполнение 8938](https://n8n-itmo.cyrweb.ru/workflow/fSKPIp3KxTdLHguI/executions/8938). Для живого показа успешного повтора остановите второй процесс и запустите `PORT=4174 npm start` из `practices/practice_08`, затем нажмите **Повторить** на той же странице.
5. Включите ширину 375 px, пройдите форму с Tab и Enter. Запустите `make -C practices/practice_08/defence test`, покажите `page.route()` и пару `{classification: null}` / `{classification: {type: 'bug', confidence: 0.95}}`. В тесте с задержкой запрос удерживает `Promise`, поэтому двойной клик, два Enter и дополнительный `requestSubmit()` проверяются в контролируемом состоянии ожидания. Синхронный `useRef` в форме закрывает промежуток до React-рендера заблокированной кнопки.
6. Откройте [журнал прогона](evidence/client-tests.txt) и [падение при удалении сообщения](evidence/mutation-test.txt). Замечания по макету и стилям фокуса сохранены в [разборе работы с AI](ai.md).
