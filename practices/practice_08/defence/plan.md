# План практики 8

1. Выбрать сценарий дежурного поддержки из практики 7.2. По заголовку и описанию Issue получить рекомендацию по категории. При уверенности ниже 80% или ответе `unknown` предложить ручной разбор.
2. Спроектировать с Codex интерактивный HTML-прототип. Сохранить рабочие состояния формы и результата, проверить порядок чтения на узком экране, зафиксировать изменения по итогам проверки макета.
3. Собрать интерфейс на React, TypeScript и Mantine. Вынести палитру, шрифты и интервалы в тему. Подключить серверный адаптер к защищённому webhook n8n, который вызывает существующий Sub-workflow классификатора. Проверить валидный ввод, ошибки, повтор после сбоя, фокус и блокировку отправки до завершения запроса.
4. Написать с Codex браузерные тесты Playwright. Перехватывать только HTTP-границу клиента. Проверить контракт, видимый результат, валидацию, клавиатуру, узкий экран и число запросов. Временно скрыть сообщение об ошибке, подтвердить падение нужного теста и повторить прогон после восстановления.
5. Запустить сценарий с учебным n8n. Снять экран приложения в ключевых состояниях, записать ID реальных исполнений, сохранить команды, промпты, вывод тестов и матрицу приёмки.
6. Сверить изменения с 11 критериями практики. Проверить дерево коммита на локальные файлы и секреты. Отправить текущую ветку и открыть PR к ветке 7.2, чтобы в ревью были видны изменения этой практики.
